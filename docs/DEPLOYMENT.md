# Развёртывание и откат

Этот репозиторий публикует транспортные сборки. Существующий WireGuard, ключи, маршруты, NAT и панель остаются отдельными компонентами. Примеры используют документационный адрес198.51.100.10 и фиктивный ключ; перед использованием заменить их своими значениями.

Для нового независимого экземпляра доступны [установка одной командой](../README.md#установка-одной-командой) и [подробные параметры и удаление](INSTALL.md). Установщик не меняет действующие VPN или настройки Keenetic. Описанные ниже ручные действия относятся к отдельному сценарию адресной замены уже работающего транспорта.

## Keenetic Entware

1. Проверить `uname -m`: профиль рассчитан на aarch64/Cortex-A53.
2. Сохранить NDM-конфиг, действующий бинарник, obfuscator.conf, init-скрипт и его права. Проверить свободный локальный UDP-порт.
3. Проверить SHA256 ARM64-артефакта. Для нового независимого процесса использовать имя `wgot-client` (меньше15 символов), отдельные конфиг и init-скрипт. Существующие pca-obfs/phobos-obfs не перезаписывать автоматически.
4. Шаблон `examples/S97wgot-client.example` выключен (`ENABLED=no`). Проверить конфиг и ключ до ручного включения. Клиент STUN должен подключаться к принимающему STUN/AUTO серверу.
5. При подключении существующего WireGuard через локальный UDP endpoint сохранять его ключи и выбранную маршрутизацию. Профили и политики пользователей этот проект автоматически не создаёт.
6. Для проверенной конфигурации STUN использовался MTU1380; проверять MTU фактического пути. Добавление заголовка к прежнему большому пакету может ухудшить работу.

После замены процесса может понадобиться новый handshake только соответствующего WireGuard-интерфейса. Не использовать `killall wg-obfuscator` — это затронет независимые туннели.

## Linux VPS

1. Проверить x86_64, SHA256 артефакта и его `--help`.
2. Сохранить исходный unit/config и бинарник. Установить отдельное имя `wgot-server`, затем адаптировать шаблон `examples/wgot-server@.service` к выбранной конфигурации.
3. Проверить лимиты на **хосте**: `sysctl net.core.rmem_max net.core.wmem_max`. Если они ниже1 МиБ/512 КиБ, увеличить только пределы с сохранением прежних значений. Не уменьшать существующие более высокие значения и не менять buffer defaults без отдельного основания.
4. В Docker пределы могут требовать настройки на хосте; переменные `/proc/sys/net/core` внутри netns могут отсутствовать. Не пересоздавать контейнер только ради проверки без сохранения его конфигурации.
5. Ограничить доступ к внутреннему WireGuard UDP-порту согласно архитектуре своего сервера. Unit из примера не создаёт firewall/NAT и не меняет сетевые политики.
6. Для существующего PCA допустим адресный systemd override одного обфускатора, использующий отдельный бинарник и прежний config. Оригинальный бинарник сохранять для отката.

Изменения действующего Phobos с MEDIA/TLS/SOCKS5 требуют совместимости его собственного протокола и менеджера процессов. Эти примеры относятся к ClusterM-транспорту; проверенная контейнерная сборка Phobos ранее ускорялась своими буферами/режимом/MTU без её замены на этот бинарник.

## Проверка

Проверить свежий handshake, реальный HTTPS и внешний IP через выбранный интерфейс. Затем последовательно измерить полезный трафик и CPU. Для сравнения нагрузки нужны одинаковые достигнутые скорости; низкий CPU при недополученных данных не означает лучшую эффективность.

Не считать наличие процесса или HTTP200 панели доказательством работы тракта. При проверке не менять политики и назначения устройств; сравнить конфиги и состояние остальных VPN до/после.

## Откат

Остановить только новый/изменённый процесс. Восстановить его прежний бинарник или убрать только собственный override, выполнить daemon-reload при systemd, запустить исходный unit. Вернуть клиентский transport config и при необходимости переподключить соответствующий интерфейс. Если повышались системные пределы, вернуть сохранённые значения и убрать только собственный sysctl-файл.

Не восстанавливать полный старый NDM-конфиг поверх новых пользовательских изменений, не очищать firewall целиком и не перезапускать другие VPN. После отката снова проверить payload и маршруты.
