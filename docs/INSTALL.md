# Установщик транспорта

Однострочные команды для VPS, Keenetic и приватного GitHub находятся в [README](../README.md#установка-одной-командой). Установка транспорта не создаёт полноценный VPN: WireGuard и его peer должны быть настроены отдельно. Существующие ключи WireGuard установщик не читает.

## Требования

- VPS: Linux x86-64, запущенный systemd, root, стандартные POSIX-инструменты и `sha256sum`.
- Keenetic: Entware в `/opt`, `uname -m` = `aarch64`, CPU совместим с Cortex-A53, root в Entware SSH. MIPS, ARM32 и прочие архитектуры не поддержаны этими prebuilt.
- Для онлайн-установки: curl с поддержкой TLS и актуальными CA-сертификатами. Установщик не отключает проверку сертификатов и не устанавливает пакеты автоматически.
- Для проверки свободных портов должны читаться обе таблицы `/proc/net/udp` и `/proc/net/udp6`. Отсутствие таблицы IPv6 приводит к отказу: занятость порта не угадывается.
- Совпадающий ключ транспорта на обеих сторонах: 32–128 символов `A-Z a-z 0-9 _ + = . / -`, без пробелов и переводов строки внутри ключа. Конечный LF файла допустим. VPS генерирует случайный ключ, если файл не указан; Keenetic запрашивает его скрыто через `/dev/tty`.

## Параметры

```text
sh install.sh vps|keenetic --target HOST:PORT [параметры]
```

| Параметр | Значение |
| --- | --- |
| `--target HOST:PORT` | Обязательный. VPS: endpoint выбранного WireGuard. Keenetic: внешний endpoint установленного серверного транспорта. IPv4 или DNS-имя; IPv6 не поддержан самим транспортом. |
| `--name main` | 1–8 строчных латинских букв/цифр. Другое имя создаёт независимый экземпляр. |
| `--listen-port auto` | Свободный порт `24000–24999`; выбранный порт выводится до установки. Явный порт: `1024–65535`. Проверяются все адреса обеих UDP-таблиц. |
| `--key-file FILE` | Прочитать ключ из файла; его значение не появляется в аргументах процесса или отчёте. Хранить входной файл с правами `600`. |
| `--source-dir DIR` | Взять prebuilt из локальной копии. Проверка встроенного SHA256 остаётся обязательной. |
| `--dry-run` | Только проверить платформу, пути и порт, вывести план; без скачивания, чтения ключа и записи. Можно без root. |
| `--no-start` | Установить файлы, но не запускать и не включать автозапуск. Порт при этом не резервируется. |

Повторная установка с тем же именем отказывается от перезаписи, даже если сервис остановлен. Обновление действующего экземпляра не выполняется автоматически. Для проверки новой версии использовать другое имя и свободный порт.

## Что создаётся

| | VPS | Keenetic |
| --- | --- | --- |
| Каталог экземпляра | `/usr/local/lib/wgot/main/` | `/opt/etc/wgot/main/` |
| Имя бинарника/процесса | `wgots-main` | `wgotc-main` |
| Сервис | `/etc/systemd/system/wgot-main.service` | `/opt/etc/init.d/S97wgot-main` |
| Конфиг | `transport.conf` внутри каталога | `transport.conf` внутри каталога |
| Ключ | `shared-key.txt` внутри каталога | `shared-key.txt` внутри каталога |
| Состояние | `install.info`; лог в journal | `install.info`, `control`, `pid`, `runtime.log`, флаг `enabled` |
| Прослушивание | `0.0.0.0:ПОРТ`, AUTO | `127.0.0.1:ПОРТ`, STUN |

Каталог имеет права `700`, конфиг и ключ — `600`. Ключ не выводится. Установщик проверяет SHA256 до исполнения бинарника. Затем выполняет `--help` для проверки запуска на данной системе. GitHub-токен не сохраняется в каталоге экземпляра.

До записи проверяются существующие файлы, symlink, одноимённые systemd units из других каталогов и занятые UDP-порты. Создание каталога экземпляра атомарное, сервис записывается с `noclobber`. При ошибке после создания нового экземпляра удаляются только его известные файлы. Если systemd не может остановить unit либо Keenetic не может подтвердить владельца PID или остановить его, файлы сохраняются для ручной проверки. Проверка порта и последующий bind не атомарны: при гонке запуска ошибка приводит к откату нового экземпляра.

Управление Keenetic проверяет `/proc/PID/exe` и точный путь конфига из аргументов процесса перед остановкой. Общие `killall`, `pidof wg-obfuscator` и rc.func с поиском по общему имени не используются. Неподтверждённый или устаревший PID-файл требует ручной проверки, прежде чем его удалить. Файл `runtime.log` содержит только WARN/ERROR; при долгой эксплуатации контролировать его размер.

## Проверка и запуск

VPS:

```sh
systemctl status wgot-main.service
journalctl -u wgot-main.service -n 30 --no-pager
# После --no-start, вручную:
systemctl enable --now wgot-main.service
```

Keenetic:

```sh
/opt/etc/wgot/main/control status
# После --no-start: запустить сейчас и разрешить запуск при следующей загрузке
touch /opt/etc/wgot/main/enabled
/opt/etc/init.d/S97wgot-main start
```

Работа процесса и bind UDP-порта проверяются установщиком при обычном запуске. Это не проверка полноценного VPN. После ручного подключения WireGuard к локальному endpoint проверить свежий handshake, HTTPS и внешний IP через конкретный интерфейс. Сравнить политики и назначения устройств до/после ручных действий. Установщик их не читает и не меняет.

## Остановка и удаление только своего экземпляра

Команды ниже предназначены для имени `main`; для другого имени заменить его во всех путях. Сначала убедиться, что это нужный экземпляр. Остановку можно отменить повторным запуском. Ключ сохранить отдельно, если он нужен для восстановления.

VPS — остановить и отключить автозапуск:

```sh
systemctl disable --now wgot-main.service
```

Затем при необходимости удалить только созданные файлы:

```sh
rm /etc/systemd/system/wgot-main.service
systemctl daemon-reload
rm /usr/local/lib/wgot/main/wgots-main /usr/local/lib/wgot/main/transport.conf /usr/local/lib/wgot/main/shared-key.txt /usr/local/lib/wgot/main/install.info
rmdir /usr/local/lib/wgot/main
```

Keenetic — отключить автозапуск и остановить только свой процесс:

```sh
rm -f /opt/etc/wgot/main/enabled
/opt/etc/wgot/main/control stop
```

Только после успешной остановки:

```sh
rm /opt/etc/init.d/S97wgot-main
rm -f /opt/etc/wgot/main/wgotc-main /opt/etc/wgot/main/transport.conf /opt/etc/wgot/main/shared-key.txt /opt/etc/wgot/main/install.info /opt/etc/wgot/main/control /opt/etc/wgot/main/runtime.log /opt/etc/wgot/main/pid
rmdir /opt/etc/wgot/main
```

Рекурсивное удаление общих каталогов не требуется. Установщик не делает резервную копию чужих VPN, поскольку не перезаписывает их. Если endpoint WireGuard менялся вручную, его возвращают отдельно вручную; политики и назначения устройств для удаления транспорта менять не требуется.
